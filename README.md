# Interactive Map — Temperature / Wind / Insolation

Тестовое задание: React + TypeScript приложение с интерактивной картой, тремя пользовательскими GIS-слоями, timeline, синхронизированным графиком на Recharts и 3D-моделями достопримечательностей Бишкека. Состояние организовано через Vedro.

🌐 **Demo:** https://pakrulin.github.io/gigiMap/

📦 **Repo:** https://github.com/pakrulin/gigiMap

## Стек

- **React 18 + TypeScript + Vite**
- **Vedro** — управление состоянием
- **MapLibre GL JS v6** — карта
- **Recharts** — графики
- **deck.gl** (`@deck.gl/mapbox` + `@deck.gl/mesh-layers`) — 3D-модели

## Архитектура

```
src/
├── store/          # Vedro store (единственный источник истины)
├── data/           # типы, mock API, генераторы данных, blend-утилита
├── map/            # интеграция с MapLibre + реестр слоёв + стратегии + 3D
│   └── strategies/ # heatmap / circle / polygon
├── timeline/       # временная шкала
├── charts/         # Recharts
└── components/     # UI-компоненты (панель слоёв)
```

Границы ответственности:

- **store** — только состояние и точка сборки Vedro. Никакой логики отображения.
- **data** — чистые функции (генераторы mock-данных), API с `AbortSignal`, интерполяция `blendLayerData`.
- **map** — знает про MapLibre и deck.gl, ничего не знает про Recharts/timeline. Получает данные через селекторы.
- **timeline** — управляет `selectedTimeIndex`. Ничего не знает про карту.
- **charts** — визуализация временных рядов. Клик по графику → dispatch.
- **components** — чистый UI. Индикатор загрузки изолирован в подкомпонент `LayerStatus`, чтобы ре-рендерить только нужный слой.

## Почему MapLibre GL JS

- Открытый исходный код, нет API-ключа и vendor lock-in (форк Mapbox GL JS v1 после смены лицензии).
- WebGL-рендеринг — высокая производительность на больших GeoJSON.
- Из коробки поддерживает `heatmap`, `circle`, `fill`, `fill-extrusion` (3D), растровые слои — всё, что нужно для GIS.
- Хорошо интегрируется с React через прямой доступ к инстансу карты (`useRef` + `useEffect`).

Отклонены: Mapbox GL (платный, требует ключ), Leaflet (слабая работа с вектором и 3D), OpenLayers (тяжёлый, оверкилл для задачи).

**Базовый стиль:** OpenFreeMap Liberty — подробный векторный стиль без API-ключа.

## Состояние в Vedro

Один стор на всё приложение. Хранит:

- `activeLayers: LayerId[]` — включённые слои;
- `timePoints: TimePoint[]` — временная шкала (единая для всех слоёв);
- `selectedTimeIndex: number` — выбранная точка;
- `layerDataCache: Record<LayerId, Record<timestamp, LayerData>>` — кэш данных;
- `loading` / `errors` по каждому слою.

Обновления — через `dispatch` Vedro:

- `dispatch('selectedTimeIndex', i)` — простое поле;
- `dispatch((state) => ({ activeLayers: next }))` — функциональное обновление, возвращаем только изменившуюся часть.

`useSelector` принимает селектор, возвращающий **объект** с нужными полями, что даёт точечные ре-рендеры: компонент перерисовывается, только если изменилась выбранная им часть стора.

## Поток данных: Timeline → Store → Map + Chart

```
Timeline  ──dispatch──▶  selectedTimeIndex в Vedro
                                │
                                ▼
                       useAppSelector в:
                    ┌───────────┴────────────┐
                    ▼                        ▼
              useMapLayers             TimeSeriesChart
                    │                        │
                    ▼                        ▼
              MapLibre слои            Recharts LineChart
```

- **Timeline** → меняет `selectedTimeIndex`.
- **useMapLayers** читает `selectedTimeIndex`, `activeLayers`, `layerDataCache`; грузит недостающие данные и вызывает стратегию отображения.
- **TimeSeriesChart** читает те же поля, строит ряды. Клик по графику → `dispatch('selectedTimeIndex', i)` — двусторонняя синхронизация.

## GIS-слои

Единый реестр `LAYER_REGISTRY` описывает каждый слой: `id`, `name`, `color`, `unit`, `renderType`.

Стратегии отображения (`heatmap`, `circle`, `polygon`) реализуют интерфейс `sync(map, config, data, isActive)`. Чтобы добавить новый тип — регистрируем стратегию в `strategies/index.ts`.

Данные слоя генерируются детерминированно (сетка 25×25 = 625 точек) с учётом:

- суточного хода температуры;
- «теплового острова» в центре города;
- рельефных волн и «облачных пятен» для инсоляции.

## Плавное переключение времени

При смене временной точки данные **интерполируются** между двумя состояниями через `requestAnimationFrame` и кривую `easeInOutCubic` (450 мс). Анимация работает вне React — на каждом кадре вызывается `setData()` на MapLibre-источнике, что даёт 0 ре-рендеров React за весь переход.

## 3D-модели

Поверх карты размещены две 3D-модели (Бишкек):

| Модель           | Координаты             | Файл                       |
| ---------------- | ---------------------- | -------------------------- |
| Колесо обозрения | `74.6002, 42.8797`     | `/models/ferris-wheel.glb` |
| Памятник Ленину  | `74.606187, 42.877582` | `/models/lenin.glb`        |

Реализация: `use3DModels` хук в `src/map/use3DModels.ts`. Каждая модель — отдельный `ScenegraphLayer` с прямым URL в `scenegraph` (строка, не функция — это критично для триггера загрузки). Overlay — `MapboxOverlay` с `interleaved: true`.

**Совместимость MapLibre v6 и deck.gl**: MapLibre v6 переместил `map.transform` в `map._camera.transform`, а deck.gl читает старый путь. Решено шимом `installMapTransformCompat()` в `src/map/maplibreCompat.ts`, который добавляет геттер `transform` на прототип `Map` до создания карты.

## Асинхронность и race conditions

- **Кэш по `(layerId, timestamp)`** — каждый ответ пишется в свой слот. Карта всегда читает актуальный слот.
- **`requestedRef: Set<string>`** — гарантирует, что запрос для пары (слой, время) стартует ровно один раз.
- **`AbortController`** на каждый запрос + отмена всех при размонтировании компонента.
- Быстрое переключение timeline не «портит» состояние: пришедшие данные ложатся в свой кэш-слот и не перезаписывают актуальные.
- **Батчинг dispatch**: `loading` + `errors` обновляются одним вызовом, чтобы не плодить ре-рендеры.

## Производительность

- Точечные ре-рендеры за счёт `useSelector` в Vedro: каждый компонент читает только нужные поля.
- `LayerStatus` — изолированный компонент для индикатора загрузки, чтобы не ре-рендерить всю панель.
- Синхронизация карты выполняется одним `useEffect`, а не в каждом компоненте.
- `setData` на существующем источнике вместо удаления/добавления — дешевле.
- Данные слоя генерируются детерминированно, одинаковый timestamp → одинаковые данные (кэш работает корректно).
- Recharts с `isAnimationActive={false}` и лёгким `LineChart` — нет лишних перерисовок.
- Плавная анимация переключения времени идёт мимо React (RAF + `setData`).

## Масштабирование до 100+ слоёв

- Реестр слоёв (`LAYER_REGISTRY`) + стратегии рендеринга — добавление слоя сводится к регистрации конфига и (опционально) новой стратегии.
- Панель слоёв легко виртуализируется при большом количестве.
- Кэш по `(layerId, timestamp)` естественно расширяется; при необходимости — LRU-эвикция.
- Тяжёлую генерацию или парсинг GeoJSON можно унести в Web Worker без изменения UI.

## Компромиссы

- **Mock-данные** вместо backend: цель — показать архитектуру, а не интеграцию.
- **Минимальный UI**: задание прямо говорит, что дизайн не важен.
- **Один график**: достаточно для демонстрации синхронизации; архитектура позволяет добавить любое количество.
- **Кэш в памяти**: при перезагрузке теряется; для продакшена — IndexedDB / серверный кэш.
- **3D-модели** — публичные GLB, не исторически точные копии. Задача — показать интеграцию deck.gl + MapLibre.
- **Шим для deck.gl + MapLibre v6** — временное решение; при переходе на официальную поддержку v6 шим можно убрать.
